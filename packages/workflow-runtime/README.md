# @flowaid/workflow-runtime

The engine that runs compiled flowaid workflows: an event-sourced scheduler whose decisions are
pure functions of the run's event log, and the orchestration around it — fenced appends,
leases, recovery, durable timers, human tasks, subflows — over pluggable stores and queues.
Design: [ARCHITECTURE.md §5](../../docs/design/ARCHITECTURE.md).

| Module                                       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `initialState` / `reduce` / `ready` / `step` | The pure scheduler. `reduce` folds events into `SchedulerState` (structural sharing, JSON-serialisable for checkpoints); `ready` applies the activation rules (OR within exclusive groups, AND across them, eager pruning, join modes); `step(plan, state, trigger, ctx)` returns the events to append and the effects to perform                                                                                                             |
| Node kinds                                   | input, output (with early exit), task, branch, join (`all`/`any`/`count`/`race` with private-subgraph cancellation, timeouts), loop (carry, `exitWhen`, iteration/time/cost/token bounds, `exhausted` routing), foreach (concurrency, `fail_fast`/`collect`/`skip`, collect and reduce), subflow (depth limit, timeout), wait (delay/timestamp/event), human (approve/reject/choose/submit, expiry routes/fails/escalates, escalation timers) |
| Reliability                                  | Retries on durable timers with full-jitter backoff and `retryAfterMs`; never retries non-idempotent nodes; crash recovery re-runs `safe`/`keyed` nodes and fails `none` ones with `NONIDEMPOTENT_INTERRUPTED`; cancellation, run deadlines and cost/token/node-run bounds                                                                                                                                                                     |
| Replay                                       | `inputHash = sha256(canonical inputs + config + type version)`; recorded replay reuses matching node runs; restart-from-node via `neverReuse`; stable idempotency keys for `keyed` nodes                                                                                                                                                                                                                                                      |
| `executeTask` / `NodeRegistry`               | Validates config, input and output against the node's schemas, builds the capability-scoped `ctx`, enforces the node timeout, turns logs, metrics and provider/tool calls into events                                                                                                                                                                                                                                                         |
| `registryProviderAccess`                     | `ctx.providers` over a `ProviderRegistry`, emitting DECISION_REQUESTED/COMPLETED, PROVIDER_FAILOVER and GENERATION_COMPLETED                                                                                                                                                                                                                                                                                                                  |
| `Orchestrator`                               | Per-run serialisation, lease take-over with `RUN_LEASE_TAKEN`, recovery from checkpoint + tail, one fenced append per step, publish, checkpoints every 200 events, effects; maintenance fires timers (compare-and-set), renews and reaps leases, picks up cancel requests                                                                                                                                                                     |
| `createEventRedactor`                        | Write-time redaction: per-node mask/hash/drop rules, `doNotPersist` outputs, learned secrets                                                                                                                                                                                                                                                                                                                                                  |
| `runLocally`                                 | The whole runtime in one process (CODE_EXPORT.md §2) — what exported code packages and `workflow run --local` call; `nodes` and `providers` are required                                                                                                                                                                                                                                                                                      |
| Stores and queues                            | `MemoryRunStore`, `MemoryQueueDriver`, `MemoryEventBus`; `BullMqQueueDriver` and `RedisEventBus` (with `REDIS_URL`); the Postgres ones live in `@flowaid/database`                                                                                                                                                                                                                                                                            |
| `@flowaid/workflow-runtime/testing`          | `simulate()` (deterministic driver with fake executors and a fake clock) and the `RunStore`/`QueueDriver`/`EventBus` contract suite                                                                                                                                                                                                                                                                                                           |

## Guarantees the tests hold it to

- Property tests (fast-check, random executor behaviour on real plans): the state `step` builds
  equals a from-scratch reduction of the log; a serialised checkpoint plus the rest of the log
  equals the full reduction for any split; `seq` is dense; the terminal event is last; every
  scheduled node run ends; the run's spend equals what its nodes reported.
- Golden runs of the compiler's demo plans (support triage: auto, escalation, human review;
  research agent: a bounded loop with a foreach body, exit conditions, exhaustion routing).
- One test per construct in `constructs.test.ts`; crash take-over, lease serialisation and
  once-only timers with two orchestrators on one store.
- The contract suite runs against the memory stores here, and against BullMQ and Redis in the
  CI `integration` job.
