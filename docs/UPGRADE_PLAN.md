# flowaid — Upgrade plan (full system upgrade)

Generated 2026-09-22 from the 165 verified review findings in `docs/archive/review-2026-09/*.md` (lenses: design-coherence, spec-gap, workflow-core, ui, devops, security, backlog). Machine-readable copy: `docs/upgrade-plan.json` (same ids). Track J (§6) was added on 2026-09-23 from the Jev engineering gap analysis (`docs/design/JEV_ENGINEERING.md`). This plan **replaces** the wave sequencing of `docs/design/IMPLEMENTATION_PLAN.md` (the waves are retired; nothing resumes from them — every phase below is planned fresh from what is on disk today); the work-package definitions (WP-xx) remain the reference for files, done criteria and tests and are cited by the items.

## 1. Executive summary

1. **State.** Four packages are real and green (`config`, `shared` 76 tests, `env` 24, `workflow-core` 1 856, `ui` 618 with a playground); the design is complete on paper (ARCHITECTURE, CONTRACTS, DATABASE, API, UI, CODE_EXPORT, LANGCHAIN); nothing is committed, no app exists, `pnpm boundaries` and `pnpm lint` are red, there is no CI.
2. **Biggest risks.** (a) The foundation cannot ship as-is: packages export `.ts` sources (Docker/`pnpm pack` cannot run them), `workflow-core` pulls `node:crypto` through `shared` so the browser compiler cannot load, and the boundaries config disagrees with the architecture. (b) The frozen contracts and the built UI have drifted apart: `packages/ui` mirrors its own status/event/hint vocabularies (wrong node-run statuses, ~25 missing event types, `x-flowaid` instead of `x-ui`, handle ids and edge types off-spec). (c) Twelve security holes in the design and the compose stack (master key in the sandbox container, `.env` in every image layer, RLS that the owner role bypasses, unthrottled login, `?t=` review tokens, `worker_threads` presented as isolation). (d) Real evaluator bugs in `workflow-core` (false `E_TYPE_MISMATCH` on nullable unions, ReDoS, timezone-dependent dates, step budget that blocks `map` over 5 000 items).
3. **What "upgraded" means.** Phase 0 makes what exists correct, secure and enforced (green CI on boundaries, lint, format, types, tests, coverage; contracts-consistent UI; hardened env/compose; corrected design docs — the doc part is already applied). Phases 1–5 build the platform along the dependency DAG to the acceptance journey from a clean clone (`docker compose up` → build → publish → run → approve → replay → v2 → compare → evaluations → Download code), which is the release gate. Phase 6 completes the spec (node catalog, routing/advisor, observability surfaces, importer/docs, knowledge, agents, identity extras) behind feature keys so nothing unfinished reaches navigation.
4. **Scope control.** Duplicates across lenses are merged (e.g. five findings on the same compose/`.env` problem → one item); the contract changes the review proved necessary are tracked as RFC-0001…0012 in `docs/design/RFCS.md` and applied by the implementing items, `CONTRACTS.ts` stays frozen until then; 19 alternatives are declined with reasons (§4).
5. **Shape.** 7 phases, 56 items; Phase 0 (20 items) and Phases 1–4 and 6 run as parallel batches, Phase 5 is serial; the critical path is P0 → P1-01/P1-03/P1-04 → P2-01 → P3-01 → P4-01 → P5-01 → P5-02 → P5-03 (≈ XL+XL+XL+M+XL+XL+L of one engineer each, ~5–6 months wall-clock on that chain, the other lanes fit inside it). A phase-independent **track J** (22 items, §6) implements the Jev engineering addendum; its first seven items live in the standalone `@flowaid/jev` package (depends only on `workflow-core` + `shared`) and can start now.
6. **Owner requirements honoured.** LangChain (P3-04, P4-03) and Download code (P4-04) are in the plan, but LangChain is off the acceptance path (bundled plugin, `features.langchain`) and code export is on it.
7. **Gate for every item** is a named test set, not a review; every finding id appears in at least one item's `resolves` list (coverage is asserted by the generator that produced this file).
8. **First actions** (day one, all parallel): P0-01 boundaries/lint, P0-02 SHA-256, P0-03 dist exports, P0-04 pins/format, P0-05 CI, P0-06 docker/compose, P0-07 env guards — after which every later item lands behind a green pipeline.
9. **Do not resume old sequencing.** The Wave 2 diagram made `nodes-langchain` a worker prerequisite and Wave 5 put evaluation after the gate; both are corrected in the docs and this plan.
10. **Definition of done for the upgrade**: `e2e.yml` green from a clean clone with recorded providers, the same journey passing with live TypeSafe/OpenAI keys, and no feature key true whose backend is not real.

## 2. How to read the phases

Track J (§6) is not a phase: its items carry explicit hard dependencies instead of a phase gate. Each phase is a batch; `parallel: true` means every item in it can start once the previous phase's gate is green (items may name a prerequisite inside the same phase in their text, e.g. P1-02 imports the contract suite that P2-01 exports and uses a local copy until then). Effort: S ≤ 1 day, M 2–4 days, L 1–2 weeks, XL 2–4 weeks (one engineer). `Resolves` lists the review finding ids the item closes; a finding split into a documentation part and a code part appears under both items.
