# flowaid — HTTP API (`apps/api`, Fastify 5, OpenAPI 3.1)

Base path `/v1` (webhook ingress at `/hooks`, MCP server at `/mcp`). Every route is declared with `fastify-type-provider-zod` (`params`, `querystring`, `body`, `headers`, `response`) and a required `config.auth`; a route without `auth` fails to register at startup. `@fastify/swagger` emits OpenAPI 3.1 at `GET /v1/openapi.json`; Scalar reference at `GET /docs`. The SDK (`openapi-typescript` + hand-written `Flowaid`/`RunHandle`) and the CLI are generated from that document.

Schema names below refer to `CONTRACTS.ts` where they exist there; API-only DTOs are defined in §7.

## 1. Auth, principals, scopes

```ts
type AuthMode =
  | "session"
  | "api_key"
  | "session_or_api_key"
  | "review_token"
  | "webhook"
  | "mcp_token"
  | "public"
  | "internal";
interface Principal {
  type: "user" | "api_key" | "review_token" | "mcp_token" | "webhook" | "system"; // webhook: id = webhooks row id, scopes { runs:create } pinned to its workflow/environment; mcp_token: an api_keys service-account row (scope mcp:serve)
  id: string;
  workspaceId: string;
  role: WorkspaceRole | null;
  scopes: ReadonlySet<Scope>;
  environmentId: string | null; // api keys / mcp tokens pinned to an environment
  workflowIds: ReadonlySet<string> | null;
}
```

- **Session**: `POST /v1/auth/login` sets `__Host-fa_session` (`Path=/`, `Secure`, `HttpOnly`, `SameSite=Lax`; ES256 JWT, 15 min, claims `sub`, `sid`, `tv` **only** — no workspace, no role) and `fa_refresh` (`Path=/v1/auth/refresh`, `Secure`, `HttpOnly`, `SameSite=Strict`, 30 d, rotated on use, hashed in `refresh_tokens`). `Secure` is dropped only under `FLOWAID_ALLOW_INSECURE_HTTP=true`. The **workspace is resolved per request** from `X-Workspace: <slug>` (the web app forwards its `[ws]` route segment), defaulting to the user's most recently used workspace; the **role is read from `memberships` per request** (cached 60 s per `sid`), so a demotion or removal takes effect within a minute. `tv` is `users.token_version`, bumped by password change, `POST /v1/auth/logout-all`, member removal and role change; a stale `tv` is 401. Login revokes any presented refresh token and mints a new family (`refresh_tokens.family_id`, `sid = family_id`); presenting an already-rotated refresh token revokes the whole family and audits `auth.refresh_reuse_detected`. State-changing session requests — including `/v1/auth/refresh` and `/v1/auth/logout` — must send `X-Requested-With: flowaid` (CSRF via CORS preflight); web and api must be same-site, and the api refuses `CORS_ORIGINS` entries cross-site with `FLOWAID_BASE_URL` unless `FLOWAID_ALLOW_CROSS_SITE=true`. `POST /v1/auth/login` is throttled 20/min per IP and 10 per 15 min per lower-cased email, runs argon2 against a fixed dummy hash for unknown emails (constant time) and audits `auth.login`/`auth.login_failed { emailHash }`. With `REDIS_URL` the throttles, the request rate limits and the webhook signature replay cache live in Redis (keys under `flowaid:limits:`), so they hold across api replicas; without it they are per process. A Redis error lets a request past the request rate limit (ioredis reports the connection error) but fails a sign-in or a signed webhook delivery.
- **API keys**: `Authorization: Bearer fa_<live|test>_<32 base62 random>_<6 base62 crc32>` (the checksum lets secret scanners verify a key offline; `test` keys can only be pinned to non-protected environments) → sha256 lookup → scopes: stored scopes intersected at request time with the creator's _current_ role (a demoted creator's key loses scopes; a removed creator's key is revoked) unless the key is a service account (`is_service_account`, admin-only to create, scopes not capped); optional `environmentId` and `workflowIds` pins; `expires_at` defaults to 365 d; `last_used_at` is written at most once per minute. Shown once at creation and on `POST /v1/api-keys/:id/rotate { graceMinutes?: 0..1440 }` (the old key expires after the grace period; audited `api_key.rotate`). MCP tokens are api keys with scope `mcp:serve`.
- **Review tokens**: `Authorization: Bearer <token>` on `/v1/review/*` — never a query string (the web route `review/[token]` receives the token in the URL _fragment_ and sends the header); 32 random bytes base64url, sha256-hashed in `human_task_review_tokens` (many links per task, revocable), `expires_at ≤ min(task.expires_at, 7 d)`; single-use means one successful `respond` (sets `used_at` in the same CAS transaction as the task), `GET` does not consume; responses carry `Cache-Control: no-store` and `Referrer-Policy: no-referrer`; 410 collapses to 404 (no existence oracle); 60/min per IP.
- **Scopes** (`Scope`): `workflows:read | workflows:write | workflows:publish | workflows:delete`, `runs:create | runs:read | runs:cancel | runs:approve | runs:replay | runs:delete`, `credentials:read | credentials:write`, `secrets:bind`, `tools:read | tools:write`, `mcp:read | mcp:write | mcp:serve`, `evaluations:read | evaluations:write`, `knowledge:read | knowledge:write`, `webhooks:write`, `schedules:write`, `members:manage`, `api_keys:manage`, `audit:read`, `admin`.
- **Roles → scopes**: `viewer` = all `*:read`; `operator` = viewer + `runs:create|cancel|approve|replay`; `editor` = operator + `workflows:write|publish`, `tools:*`, `knowledge:*`, `evaluations:*`, `secrets:bind`; `admin` = editor + `credentials:*`, `mcp:*`, `webhooks:write`, `schedules:write`, `members:manage`, `api_keys:manage`, `audit:read`, `runs:delete`, `workflows:delete`; `owner` = admin + workspace delete. Deploying to a `protected` environment requires `admin`.
- Rate limits (`@fastify/rate-limit`, Redis store with `REDIS_URL`), keyed by principal — session → `sid`, api key → key id, review token → token id, public routes → client IP (`FLOWAID_TRUST_PROXY = false | true | <cidr list>` wired to Fastify `trustProxy`): session 600/min, api key 1 200/min (`api_keys.rate_limit_per_min` overrides), other unauthenticated requests 120/min per address (all three scale with `RATE_LIMIT_MAX`, the session value: keys double, unauthenticated a fifth), `/mcp/:workspaceSlug` uses the api-key bucket, `/v1/review/*` 60/min, webhook path 300/min (60/min for `signature: 'none'`), `/run` additionally by `workspaces.settings.maxQueuedRuns` backpressure (429 `RATE_LIMIT_ERROR`). SSE streams are exempt from the request bucket but capped at `FLOWAID_SSE_MAX_STREAMS_PER_PRINCIPAL` (20) concurrent per principal and 200 per workspace (429); a stream re-checks its principal on every 15 s heartbeat (JWT `exp`/`tv`, api key `revoked_at`) and ends with `event: END {"reason":"unauthorized"}` when it no longer holds.
- Security headers via `@fastify/helmet`, CORS allow-list from env, JSON body limit 2 MiB (uploads via presigned URLs), `x-request-id` on every response, audit event on every mutation. The audit row is written inside the transaction that makes the change (`apps/api/src/plugins/audit.ts`): from the handler on, every `ctx.db.tenant`/`system` transaction that wrote anything inserts the request's row (one id per request, idempotent) before it commits, so a committed change always has its row and a rolled-back one never does, even when the process dies before the response; `onSend` then completes the row with the resource id and details (and `status` when the request failed after a committed change). A mutation that committed nothing through `ctx.db` (only enqueued work) is audited in `onSend`, after the fact.

## 2. Conventions

- Lists: `?limit` (≤ 200, default 50) `&cursor` keyset pagination `&order=asc|desc`; response `{ items: T[], next_cursor: string | null }`. `cursor = base64url(JSON.stringify([sortValue, id]))`, opaque to clients and valid indefinitely. Paginated routes and their sort keys: `GET /v1/runs` (`created_at desc, id desc`), `GET /v1/workflows` (`updated_at desc, id desc`), `GET /v1/workflows/:id/versions` (`version desc, id desc`), `GET /v1/human-tasks` (`created_at desc`), `GET /v1/audit` (`at desc`), `GET /v1/evaluations/sets/:id/cases` (`ordinal asc`), `GET /v1/evaluations/runs` (`created_at desc`), `GET /v1/webhooks/:id/deliveries` (`created_at desc`), `GET /v1/knowledge/sources/:id/documents` (`updated_at desc`), `GET /v1/runs/:id/events` (`seq asc`, cursor = seq). Workspace collections page in one fixed order and take no `order`: `GET /v1/agents`, `/v1/tools`, `/v1/mcp/servers`, `/v1/credentials`, `/v1/knowledge/sources`, `/v1/notifications`, `/v1/saved-views`, `/v1/evaluations/sets` (`name asc, id asc`), `GET /v1/mcp/exposures` (`tool_name asc, id asc`), `GET /v1/webhooks` (`path asc, id asc`), `GET /v1/schedules` (`next_run_at asc nulls last, id asc`), `GET /v1/api-keys` (`created_at desc, id desc`), `GET /v1/workspaces/:id/members` (`email asc, id asc`). Catalogs (nodes, models, providers, templates, credential types, `GET /v1/tools/catalog`) and small fixed sets (environments, a user's workspaces and sessions, deployments) return bare arrays.
- Errors: `ErrorEnvelopeSchema` — `{ error: { code, message, retryable, run_id?, node_id?, node_run_id?, details?, request_id } }`. Status from `FlowaidError.httpStatus`; request validation → `400 BAD_REQUEST` with `details.issues`; compile failure → `422 WORKFLOW_VALIDATION_ERROR` with `details.diagnostics: Diagnostic[]`; optimistic-concurrency mismatch → `412` with `details.currentRevision`.
- Optimistic concurrency on drafts: `If-Match: <draftRevision>` on `PUT /v1/workflows/:id/draft`.
- `Idempotency-Key` header on `POST …/run` (24 h, per workspace): `runs_idem_uq` is unique on `(workspace_id, idempotency_key)` and the nightly `retention.sweep` nulls `runs.idempotency_key` where `created_at < now() − 24 h`, so a key reused after the window creates a new run.
- Timestamps ISO 8601 UTC; ids uuid; money numbers in USD; snake_case in wire DTOs that the product spec names (`run_id`, `node_id`), camelCase elsewhere (definitions, events, plans are the `CONTRACTS.ts` shapes verbatim).

### 3.10 PageIndex documents (RFC-0022)

PageIndex sources are knowledge sources of kind `pageindex` (created with `POST /v1/knowledge/sources`
and `config: { indexModel, credentialId, mode, optimize }`); they never sync, and their documents
are PDFs uploaded to `/v1/pageindex/*`. The routes (status, documents and their versions, the
original file, index requests, cancellation, outlines, deletion and the `POST /v1/pageindex/query`
playground), their shapes and their errors (`PAGEINDEX_DISABLED`, `PAGEINDEX_UNAVAILABLE`,
`UNSUPPORTED_MEDIA_TYPE`, `INDEX_NOT_READY`) are specified in
[`docs/pageindex/API.md`](../pageindex/API.md). They use the knowledge scopes. The upload takes
the PDF itself as the body (at most 50 MiB, its own raw parser; every other route keeps the
2 MiB JSON limit). Deleting a document revokes it at once and queues `pageindex.cleanup`;
deleting a `pageindex` source revokes its documents, removes their upstream indexes and files,
and only then deletes the row.

### 3.11 Desktop: Close window and Quit FlowAId

When `./flowaid` (`pnpm start`) starts FlowAId on this computer, it gives the API its control
channel (`FLOWAID_LAUNCHER_URL`/`FLOWAID_LAUNCHER_TOKEN`: 127.0.0.1 and a token generated for
each launch; `scripts/control.ts`), and `features.desktop` is true. These routes are session-only
(API keys are refused) and need the `admin` scope; both mutations are audited.

| route                           | answer                                                                                                                                                                                                                                                              |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/desktop`               | `{ window: "app" \| "browser" \| "none", tray, platform, activity: { runs, approvals } }`: FlowAId's own app window, a default-browser tab or none; whether the menu bar icon is showing; what runs in the background across workspaces (what Quit would interrupt) |
| `POST /v1/desktop/window/close` | `{ closed }`: the launcher closed FlowAId's app window (FlowAId keeps running in the menu bar). `false`: a browser tab, which the page closes itself                                                                                                                |
| `POST /v1/desktop/quit`         | `202 { stopping: true }`: the launcher answers, then stops the web app, the worker and the API (`application.quit`)                                                                                                                                                 |

Without a launcher (Docker Compose, a server) they answer `409 DESKTOP_UNAVAILABLE`; a launcher
that does not answer is `503 LAUNCHER_UNAVAILABLE`.

## 4. Running a workflow

```ts
export const RunRequestSchema = z.object({
  input: JsonValueSchema,
  mode: z.enum(["sync", "async"]).default("async"),
  environmentId: z.uuid().optional(), // session: defaults to the workspace 'dev' environment; api keys: their pinned environment, else REQUIRED (400)
  versionId: z.uuid().optional(), // pin a version; default: the environment's active deployment; builder passes draft: true instead
  draft: z.boolean().default(false), // compile the current draft into an ephemeral draft version (session only)
  sessionId: z.string().max(128).optional(),
  variables: z.record(z.string(), JsonValueSchema).optional(), // only variables with source='run_input'
  labels: z.record(z.string(), z.string()).optional(),
  waitTimeoutMs: z.int().min(1000).max(300_000).default(60_000), // sync only
  stream: z.boolean().default(false), // sync only: respond as SSE instead of JSON
});
export const RunAcceptedSchema = z.object({
  run_id: z.uuid(),
  status: RunStatusSchema,
  links: z.object({ self: z.string(), stream: z.string(), output: z.string() }),
  human_task: z.object({ id: z.uuid(), url: z.string() }).optional(),
});
export const RunCompletedSchema = z.object({
  run_id: z.uuid(),
  status: z.literal("completed"),
  output: JsonValueSchema,
  outcome: z.string().nullable(),
  usage: TokenUsageSchema,
  cost_usd: z.number(),
  duration_ms: z.int(),
});
```

Flow: validate `input` against `plan.inputs` with ajv (400, no run created) → resolve version (deployment for the environment, or `versionId`, or compile the draft into a `kind='draft'` version deduplicated by `planHash`) → check every required secret is bound for the environment or answered by a key the server has for its `credentialType` (`TYPESAFE_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OLLAMA_HOST`; the same keys `GET /v1/providers` reports as `configuredOnServer`) (422 `E_SECRET_UNBOUND` with the list; deploys, including publish with `deployTo`, check the same) → monthly budget (409 `CONFLICT` with `details.reason: "budget_exceeded"` once the workspace's runs created this UTC month cost `settings.budgets.monthlyCostUsd` or more; schedules record it as `last_error`, evaluation cases fail; runs in flight continue) → backpressure check (429) → insert `runs` + `RUN_CREATED` in one transaction → enqueue `run.start` → respond:

| mode                  | outcome                          | response                                                                                                                                                            |
| --------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| async                 | —                                | `202 RunAccepted { status: 'queued' }`                                                                                                                              |
| sync                  | completed within `waitTimeoutMs` | `200 RunCompleted`                                                                                                                                                  |
| sync                  | suspended for a human            | `202 RunAccepted { status: 'waiting_for_human', human_task }`                                                                                                       |
| sync                  | still running at `waitTimeoutMs` | `202 RunAccepted { status: 'running' }` (run continues; poll or stream)                                                                                             |
| sync                  | failed / cancelled / timed out   | error envelope with the run's `error` (`run_id`, `node_id`), status from `httpStatus` (e.g. 500 `NODE_EXECUTION_ERROR`, 504 `TIMEOUT_ERROR`, 409 `CANCELLED_ERROR`) |
| sync + `stream: true` | any                              | SSE as in §5 from the first event                                                                                                                                   |

`Idempotency-Key`: same key + same body hash within 24 h → the existing run (200/202 as if just created); different body → 409 `CONFLICT`; after 24 h the sweep has cleared the key and a new run is created (§2).

## 5. SSE format (`GET /v1/runs/:id/stream`)

Headers: `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`. `Accept: text/event-stream` required.

```
: connected run=<id> after=<seq>

id: 17
event: NODE_COMPLETED
data: {"type":"NODE_COMPLETED","runId":"…","seq":17,"at":"…","nodeRunId":"…","nodeId":"intent","scope":"","attempt":1,"output":{…},"firedPorts":["done"],"usage":{…},"costUsd":0.00002,"latencyMs":412,"reused":false}

event: GENERATION_DELTA
data: {"type":"GENERATION_DELTA","runId":"…","seq":0,"at":"…","nodeRunId":"…","nodeId":"draft","scope":"","attempt":1,"ephemeral":true,"channel":"text","delta":"Hi ","index":3}

: heartbeat

id: 41
event: RUN_COMPLETED
data: {…}

event: END
data: {"run_id":"…","final_status":"completed"}
```

- `id` = `seq` for durable events (enables `Last-Event-ID` resume without gaps); ephemeral events (`GENERATION_DELTA`, `HEARTBEAT`) carry no `id` and are not replayable. **Numbering**: durable `seq` starts at 1 (`RUN_CREATED` is `seq = 1`, `runs.last_seq` starts at 0); `seq = 0` is reserved for ephemeral events; `?after` defaults to 0. `data` is exactly the redacted `RunEvent` JSON (`RunEventSchema`), so the SDK narrows on `type`.
- On connect the server replays from the DB after `Last-Event-ID`/`?after`, then subscribes to the bus and re-reads by `seq` on every notification (never trusts the bus payload). `?types=NODE_COMPLETED,DECISION_COMPLETED` filters durable events; `?include=deltas,logs` opts into ephemeral deltas and `LOG` events (default: deltas on, logs off).
- The stream ends with `event: END` after a terminal event, or after the first `RUN_WAITING` when `?until=suspend`; `?until=never` keeps it open for the builder across replays (heartbeats continue) and ends only on client close, run purge or a failed principal re-check.

### 5.1 Reconnection

- The server sends `retry: 2000` on connect. Clients (`useRunStream`, `RunHandle.stream()`) reconnect with `Last-Event-ID` using exponential backoff 1 s → 30 s with full jitter, at most 5 consecutive failed attempts before surfacing an error.
- A `Last-Event-ID` (or `?after`) below the run's oldest retained `seq` (partition dropped, run purged) is `404 NOT_FOUND { details: { reason: 'expired' } }`; the client re-reads `GET /v1/runs/:id` and `GET /v1/runs/:id/node-runs` instead of replaying.
- Streamed text is ephemeral: `GENERATION_DELTA.index` is the cumulative character offset within the node run, so a client detects a gap after a reconnect. On reconnect the UI re-reads `GET /v1/runs/:id/node-runs?nodeId=` for nodes still `running` and shows "stream resumed, partial text unavailable"; completed nodes carry their full output.
- `HumanApprovalRequired` (`CONTRACTS.ts` §8, `httpStatus 202`) is the internal signal the sync waiter converts into `202 RunAccepted { status: 'waiting_for_human' }`; it never reaches the wire as an error envelope.

## 6. Webhook ingress and callbacks

`ANY /hooks/:workspaceSlug/:path`: raw body captured (limit 2 MiB, rejected before reading when `Content-Length` exceeds it); signature verified with `timingSafeEqual` over equal-length buffers (`hmac_sha256`: `X-Signature: sha256=<hex>` or a provider-prefixed header configured on the webhook, with `X-Timestamp` ± 5 min and a nonce cache keyed `webhook:<id>:<sha256(signature)>` (TTL 10 min) — the timestamp is **required** unless `webhooks.require_timestamp = false` for providers that never send one; `token`: `X-Webhook-Token`; `none`: only in non-protected environments, the path is server-generated `<slug>-<22 base62>` and the webhook is limited to 60/min); **delivery idempotency**: the value of `webhooks.idempotency_header` (e.g. `X-GitHub-Delivery`) — or, when absent, `sha256(raw body)` within 24 h — is stored in `webhook_deliveries.external_id` (unique per webhook) and a repeat returns `200 { run_id }` of the original delivery (audited `webhook.duplicate`); rejected requests are audited `webhook.rejected { reason }` (sampled); input built as `{ body, headers, query, method }` projected by `inputPointer`; run created with `origin: 'webhook'` and the webhook row as the principal; `webhook_deliveries` row recorded. Outbound callbacks (`callbackUrl`) post `{ run_id, status, output | error }` signed `X-Flowaid-Signature: sha256=<hmac(body)>` with 5 retries (1 s, 10 s, 60 s, 5 min, 30 min) through `SafeFetch`.

### 8.2 Streaming transport

## 9. Code export (addendum, see `CODE_EXPORT.md`)

The export routes live in the main catalogue (§3.3): `GET /v1/workflow-versions/:versionId/export?format=json|yaml|ts`, `POST /v1/workflow-versions/:versionId/export/package` (202 `{ job_id }`), the draft twins `GET /v1/workflows/:id/draft/export` and `POST /v1/workflows/:id/draft/export/package` (compile first; 422 with diagnostics), `GET /v1/jobs/:id` and `GET /v1/artifacts/:id/download` (`kind='export'` ⇒ `workflows:read` on the source workflow; `Content-Disposition: attachment; filename="flowaid-<slug>-v<version>.zip"`). `:versionId` is always a uuid; there is no `'draft'` sentinel. The job runs on the worker's `jobs` queue (`Job { type: 'export.package' }`, RFC-0001), stores the zip as an artifact with `expires_at = 24 h` and `workflow_id` set, and only reads persisted (already redacted) run data; `pii`/`sensitive` fields and `{ "$redacted": true }` stubs become schema-generated placeholders listed in the package README, and `environments.variables` are never exported. Audit event `workflow.exported { workflowId, versionId, mode }`.
