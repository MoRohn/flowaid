# flowaid — LangChain integration

Status: **authoritative addendum** to `ARCHITECTURE.md` (v1.1, 2026-09-22; plugin registration and sequencing corrected by the design review). Product requirement from the owner: _the codebase must include the usage of LangChain, compartmentalized in its own part of the codebase and the README._

## 1. Position

LangChain is the largest ecosystem of model, tool, retriever, loader and vector-store integrations in the JavaScript world, and many visual flow builders are built on it. FlowAId uses it the way a runtime uses a driver library: **inside a boundary**. The core (`workflow-core`, `workflow-compiler`, `workflow-runtime`, `node-sdk`, `providers`, `apps/api`) never imports `langchain` or `@langchain/*`; the boundary check fails the build if it does. Everything LangChain lives in three places:

```
packages/langchain/          @flowaid/langchain        adapters: LangChain ⇄ flowaid providers, tools, callbacks, decisions
packages/nodes-langchain/    @flowaid/nodes-langchain  a node package (definePackage) of LangChain-powered nodes
packages/importer/…/langchain-map.ts                   the FlowAId importer's mapping of external LangChain-based nodes → nodes-langchain
```

Why a boundary: FlowAId's differentiator is typed decisions and a durable, replayable runtime. LangChain's abstractions (runnables, messages, callbacks) are excellent for _generation and retrieval plumbing_ but must not leak into the definition format, the plan, the event log or the API. Users who never touch LangChain pay nothing for it (the packages are optional plugins); users who live in LangChain get first-class access.

## 2. `@flowaid/langchain` (adapters)

Dependencies: `@langchain/core` (peer), `@flowaid/workflow-core`, `@flowaid/providers`, `@flowaid/node-sdk`, `@flowaid/shared`. Optional peers for concrete models: `@langchain/openai`, `@langchain/anthropic`, `@langchain/ollama`, `@langchain/google-genai`, `@langchain/mistralai`, `@langchain/groq`, `@langchain/community`.

| ---------------------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `LangChainGenerationProvider(model: BaseChatModel)`              | LangChain → flowaid        | Implements `GenerationProvider` (CONTRACTS.ts §15) over any LangChain chat model: streaming (`.stream()` → `GenerationChunk`s), tools (`bindTools` → `toolCalls`), structured output (`withStructuredOutput` with JSON Schema → `structured`), usage from `usage_metadata` (incl. cache read tokens), error mapping to the flowaid taxonomy, `AbortSignal` via `signal` in `RunnableConfig`. | `fromLangChainTool(tool: StructuredTool)`                        | LangChain → flowaid        | Produces a `ToolDefinition` + executor; `idempotency` from tool metadata (`metadata.idempotency`, default `none`), `capability` from `metadata.capability`.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `workflowAsLangChainTool(client, workflowId, opts)`              | flowaid → LangChain        | A `StructuredTool` whose `inputSchema` is the workflow's `inputs`; calls the workflow through `@flowaid/workflow-sdk` (server) or `runLocally` (embedded). Everything above is covered by unit tests with fake `BaseChatModel`/`StructuredTool` implementations (no network) and by recorded fixtures for `@langchain/openai` and `@langchain/anthropic` streams.

## 3. `@flowaid/nodes-langchain` (node package)

Built with `definePackage` exactly like a third-party plugin (`"flowaid": { "package": "nodePackage", "sdk": "^1" }`), so it also proves the plugin path. Node ids are prefixed `@flowaid/nodes-langchain.` per the plugin rule. Because the package ships inside the worker image rather than through `flowaid plugin add`, it is registered as a **bundled plugin** (ARCHITECTURE.md §3.5): `FLOWAID_BUNDLED_PLUGINS` (default `@flowaid/nodes-langchain`) is resolved at worker boot, its manifests are upserted into a global `plugins` row with `source = 'bundled'`, and the API serves its node manifests and its `langchain:<vendor>` provider descriptors from that row; `features.langchain` is true only while that row is enabled. It runs in a plugin host process like any other plugin. Every node declares idempotency, capabilities, credential slots and port schemas like any other node; ports are ordinary JSON Schemas, so LangChain nodes wire to decision nodes, tools and human nodes without special cases.

| node                        | category   | purpose                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `langchain.chat`            | generation | Run a LangChain chat model (`model` widget listing `langchain:*` providers) with a prompt template; streaming; tools optional. Same ports as `flowaid.ai.generate` (`text`, `structured`, `toolCalls`, `usage`).                                                                                                                                                                             |
| `langchain.runnable`        | generation | Execute a registered LCEL runnable by name with a typed input (`inputSchemaFromConfig`) and typed output (`outputSchemaFromConfig`); the callback handler records every inner model/tool call.                                                                                                                                                                                               |
| `langchain.agent`           | agent      | A LangGraph ReAct agent (`createReactAgent`) over flowaid tools (via `toLangChainTool`) and LangChain tools, bounded by flowaid budgets (`maxSteps`, `maxToolCalls`, `maxCostUsd`, `maxTokens`, timeout) and with per-tool approval through `NodeResult.suspend` (the agent's state/messages are the suspend `state`; on resume the graph continues). Emits `TOOL_CALLED/RETURNED` per step. |
| `langchain.document_loader` | retrieval  | LangChain document loaders (text, pdf, docx, csv, json, html, web/sitemap, GitHub) → `documents[]` (`{ pageContent, metadata }`).                                                                                                                                                                                                                                                            |
| `langchain.text_splitter`   | retrieval  | `@langchain/textsplitters` (recursive character, token, markdown, code) → `chunks[]`.                                                                                                                                                                                                                                                                                                        |
| `langchain.embed`           | retrieval  | LangChain `Embeddings` → `vectors[]`.                                                                                                                                                                                                                                                                                                                                                        |
| `langchain.vector_store`    | retrieval  | Upsert/query/delete against LangChain vector stores (pgvector, Chroma, Qdrant, Pinecone, Weaviate, Milvus, Elasticsearch, OpenSearch, MongoDB Atlas, Redis) through one node with a `store` discriminator; this is how FlowAId reaches the vector databases listed in the spec before native adapters exist. Query returns `hits[]` with scores and metadata.                                |
| `langchain.retriever`       | retrieval  | Any LangChain `BaseRetriever` (multi-query, contextual compression, parent-document, ensemble/hybrid with BM25) → `documents[]`.                                                                                                                                                                                                                                                             |
| `langchain.output_parser`   | data       | Structured/JSON/list parsers with retry (`OutputFixingParser`) → typed output (`outputSchemaFromConfig`).                                                                                                                                                                                                                                                                                    |

Config schemas use `x-ui` widgets from UI.md §5 (`model`, `template`, `schema`, `keyvalue`), so the inspector renders them with no special UI. Credential slots reuse the catalog types (`openai.api_key`, `anthropic.api_key`, `ollama.host`, `postgres.dsn`, `http.api_key` for hosted vector stores).

The three demo templates stay LangChain-free; a fourth template **"Knowledge assistant (LangChain RAG)"** (loader → splitter → embed → vector store → retriever → TypeSafe relevance/quality decisions → `langchain.chat` → TypeSafe safety → gate) ships in `packages/nodes-langchain/templates/` and is part of the golden-trace tests.

## 4. Importer coverage

The FlowAId importer's `langchain-map.ts` maps LangChain-based nodes from external flow exports (chat models, LLM chains, conversational chains, retrieval QA, vector stores, document loaders, text splitters, embeddings, output parsers, tools, agents) onto `@flowaid/nodes-langchain` nodes where the semantics match, with `W_IMPORT_PROVIDER_CHANGED`/`W_IMPORT_APPROXIMATE` issues explaining differences. Decision-like constructs in the source export (condition agents, routers) still map to TypeSafe decision nodes. This raises the "converted automatically" count of the migration report substantially.

## 5. Code export

`CODE_EXPORT.md` packages gain `src/langchain.ts` when the flow uses any `langchain.*` node or `langchain:*` provider: it shows the flow wrapped as a LangChain tool (`workflowAsLangChainTool`) and a minimal LangGraph agent that calls it, plus the extra dependencies in `package.json`. Flows that do not use LangChain get no LangChain dependency.

## 6. README and docs structure

The root `README.md` has a dedicated top-level section **"LangChain"** (what is and is not LangChain in FlowAId, the boundary, the two packages, a 20-line example of each direction: LangChain model inside a flow, and a flow inside a LangChain agent). Long-form docs live in `docs/langchain/` (`overview.md`, `providers.md`, `tools.md`, `nodes.md`, `rag.md`, `agents.md`, `callbacks-and-tracing.md`, `importing-external-flows.md`, `faq.md`). Each package has its own README. The boundary rule is documented in `ARCHITECTURE.md` §1.1 and enforced by the boundaries check: `boundaries.json.thirdParty` lists the only places that may import `langchain`/`@langchain/*` (`packages/langchain`, `packages/nodes-langchain`, `packages/importer/src/langchain-map.ts`, `packages/codegen/src/templates/**`, `apps/worker/src/plugins/**`), `eslint.boundaries.js` emits a `no-restricted-imports` pattern everywhere else, and `scripts/check-boundaries.test.ts` fails on a `@langchain/*` dependency in any other `package.json`. Until the packages exist, the README lists this section under "Planned integrations".
