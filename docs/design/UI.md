# flowaid — Web app (`apps/web`) and component library (`@flowaid/ui`)

Next.js 16 App Router, React 19, `@xyflow/react` 12, Tailwind 4, shadcn-style primitives on Radix, zustand 5, TanStack Query 5, CodeMirror 6. The design language is the existing `brand/IDENTITY.md`: cool graphite neutrals, one cobalt accent that means _decision_, status as a border not a fill, Instrument Sans for prose, JetBrains Mono (tabular) for anything a machine produced. Tokens are `brand/tokens.css`, synced verbatim into `packages/ui/src/tokens.css`.

## 1. Route map

```
app/
  (auth)/login                         email/password; OIDC button only when features.oidc
  (auth)/oidc/callback                 registered only when features.oidc
  (auth)/invite/[token] · password/forgot · password/reset/[token]
  review                               external reviewer page (no shell); the token arrives in the URL fragment (#t=…), is read client-side and sent as Authorization: Bearer; renders ExternalReviewView only (never run internals)
  (app)/[ws]/                          shell: left nav + top bar; workspace from slug; FEATURES from GET /v1/me
    page.tsx                           dashboard (metrics overview)
    workflows/                         table: name, env chips, last run status, success 24h sparkline, cost 24h, tags
    workflows/new                      blank | template | import (JSON/YAML/external flow export) | AI builder (when enabled)
    workflows/[id]/                    BUILDER — default tab
    workflows/[id]/runs                runs of this workflow (filters, live via /runs/stream)
    workflows/[id]/versions            version list; deploy state per environment
    workflows/[id]/versions/compare    ?a=&b=  side-by-side canvas + patch list + evaluation deltas
    workflows/[id]/deployments         environment matrix: version, variable overrides, promote, rollback
    workflows/[id]/settings            secrets binding per environment, triggers (webhooks/schedules/mcp), execution policy, privacy, evaluation set link
    runs/                              all runs (filters, saved views); live status column
    runs/[runId]                       TRACE VIEWER (tabs: Timeline · Graph · Events · Output · Logs · Cost)
    human-tasks/                       inbox: Open · Mine · Resolved; [taskId] → task page (internal `ReviewPage` with run context; the external route uses the separate `ExternalReviewPage`, whose props type has no nodeRuns/runId)
    templates/
    integrations/                      tabs: MCP servers · OpenAPI tools · Providers & models · Plugins
    knowledge/                         sources; [sourceId] documents/chunks/query playground (hidden until the RAG slice ships)
    evaluations/                       sets; sets/[setId] cases; runs/[evalRunId] report & compare
    decisions/                         decision contracts, receipts, calibration, shadow, rollout, labeling queue (JEV_ENGINEERING.md §17; hidden until features.decision_contracts)
    credentials/
    settings/                          workspace · members · api keys · environments · notifications · retention & privacy · audit
```

Server Components fetch initial data with `@flowaid/workflow-sdk` using the session cookie; interactive surfaces are Client Components with TanStack Query; SSE through `useRunStream(runId)` (fetch-based stream with `Last-Event-ID`; reconnect per API.md §5.1: 1 s → 30 s jittered backoff, ≤ 5 attempts, "stream resumed, partial text unavailable" for nodes still running). Navigation entries render only when `features[<FeatureKey>]` is true (API.md §7; quality bar: no dead navigation) — every `SideNav` item is keyed by a `FeatureKey` and a Playwright test asserts each rendered item resolves without 404.

## 2. Shell and builder layout

```
┌ TopBar (--topbar-h 44px): ⌘K · breadcrumb ws / workflow ✎ · "draft rev 12 · 2 errors" pill · [Run ▾] · [Publish] · env switch · ⋯ ┐
├ SideNav (--nav-w 208px, collapsible to 48px icons) │ Canvas (XYFlow)                              │ Inspector (--inspector-w 320px, resizable ≤ 480px) │
│  Workflows · Agents · Runs · Human tasks ·         │  dot grid --grid · minimap · zoom controls   │  header: category dot, name ✎, mono type@version    │
│  Templates · Integrations · Knowledge ·            │  nodes = NodeCard (232px)                     │  tabs: Config · Inputs · Policy · Info              │
│  Evaluations · Credentials · Settings              │  edges: control (dashed, arrowhead)          │  (edge selected: type check + projection editor)     │
│                                                    │         data (solid), template/expr (dotted)  │  (run displayed: Run tab with node-run detail)      │
├ BottomPanel (--panel-h 280px, collapsible): tabs Run · Trace · Logs · Output · Problems ───────────────────────────────────────────────────────────────┤
```

Palette entry points: `+` button in the top bar, `⌘K` command palette (nodes, actions, jump to node), right-click on the canvas, drag from the palette side sheet, and the AI builder (when enabled). Categories come from `NodeManifest.metadata.category`; fuzzy search over name/description/tags (port of an Apache-2.0 upstream `fuzzyScore`, attributed in NOTICE). MCP tools and OpenAPI operations appear as presets that instantiate `flowaid.tools.mcp` / `flowaid.tools.openapi` with config prefilled. Dropping creates a node with `config = defaults from configSchema`, id `<type suffix>_<n>`.

Keyboard: `⌘Z/⇧⌘Z` undo/redo, `⌘D` duplicate, `⌫` delete, `⌘⏎` run, `⌘S` save now, `⌘K` palette, `F` fit view, `Esc` deselect.

   │   │   └─ decision nodes render            @flowaid/ui/decision  ProbabilityRuler · ConfidenceMeter · DecisionBadge (focusable) · DistributionPopover
   │   ├─ edgeTypes: { control: ControlEdge, data: DataEdge }         labelled control edges; data edges with schema tooltip; implicit (dotted) template/expr edges

## 4. Canvas ↔ definition mapping

### 4.1 Store

```ts
// apps/web/src/builder/store.ts  (zustand + immer; patches for undo/redo)
interface BuilderState {
  workflowId: string;
  definition: WorkflowDefinition;                 // THE truth
  draftRevision: number; dirty: boolean; saving: boolean;
  catalog: NodeCatalog; toolCatalog: ToolSignature[]; subflowSignatures: Map<string, SubflowSignature>;
  compile: { plan: ExecutionPlan | null; diagnostics: Diagnostic[]; at: number };   // from the Web Worker (debounced 150 ms)
  selection: { nodes: NodeId[]; edges: string[] };
  history: { past: JsonPatch[][]; future: JsonPatch[][] };
  liveRun: { runId: string; nodeStatus: Record<string /* scope + '|' + nodeId */, NodeLiveStatus>; runStatus: RunStatus; streams: Record<string, string> } | null;
  // actions — the only way to mutate `definition`; each pushes inverse patches to history (layout-only changes are not recorded)
  addNode(node: WorkflowNode, position: XY): NodeId;
  removeNodes(ids: NodeId[]): void;                                   // also removes control edges and bindings that reference them (with a toast listing what was cleared)
  updateNodeConfig(id: NodeId, patch: JsonPatch): void;
  setBinding(id: NodeId, port: PortName, binding: Binding | undefined): void;
  setNodePolicy(id: NodeId, policy: NodePolicy | undefined): void;
  renameNode(id: NodeId, name: string): void;
  addControlEdge(from: { node: NodeId; port: PortName }, to: NodeId): Result<void, Diagnostic>;   // rejects E_EDGE_CROSSES_SCOPE / E_UNKNOWN_CONTROL_PORT with a toast
  removeControlEdges(ids: string[]): void;
  setParent(ids: NodeId[], parent: NodeId | undefined): void;         // drag into/out of a container; clears now-illegal edges with a toast
  moveNodes(positions: Record<NodeId, XY>): void;                     // definition.layout only
  setInputsSchema(schema: JsonSchema): void; setOutputsSchema(schema: JsonSchema): void;
  setVariables / setSecrets / setExecutionPolicy / setTriggers;
  undo(): void; redo(): void;
  save(): Promise<void>;                                              // PUT /v1/workflows/:id/draft with If-Match; 412 → ConflictDialog (theirs / mine / diff)
}
```

Autosave 1 s after the last change (and on blur/navigation); unsaved-changes guard on navigation; server diagnostics from the save response replace local ones only if the definition hash still matches.

### 4.2 Projection to XYFlow (pure, memoised selectors)

```ts
selectFlowNodes(state): Node<NodeCardData>[]
  // id = node.id; type = 'flowaid' ('note' for notes; 'container' for loop/foreach)
  // position = layout.nodes[id] ?? autoPlace(); parentId = node.parent; extent = 'parent' when parent set
  // data = { node, manifest?, ports: resolvedPorts(node, plan) /* from plan.nodes[id].outputs + dataIn ports */, diagnostics: byNode[id], live: liveRun?.nodeStatus[scopeKey], collapsed }
selectFlowEdges(state): Edge<EdgeData>[]
  // control: definition.edges → { id, source: from.node, sourceHandle: 'ctl:'+from.port, target: to.node, targetHandle: 'ctl-in', type: 'control', data: { fired?: boolean, pruned?: boolean } }
  // data:    plan.dataEdges  → { id: 'd:'+from.node+'.'+from.port+'→'+to.node+'.'+to.port, sourceHandle: 'out:'+from.port, targetHandle: 'in:'+to.port, type: 'data', selectable: via === 'ref', data: { via, optional, path } }
```

Handle ids are exactly `out:<port>`, `in:<port>`, `ctl:<port>`, `ctl-in` — never encoded strings (`TypedHandle` derives them from its `kind` prop; `handleId(kind, port)` is the single helper). Reverse mapping happens only through actions:

| XYFlow callback                              | store action                                                                                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `onNodesChange` (position)                   | `moveNodes`                                                                                                                                                   |
| `onNodesChange` (remove) / `onNodesDelete`   | `removeNodes`                                                                                                                                                 |
| `onConnect` from `out:*` to `in:*`           | `setBinding(target, port, { kind: 'ref', ref: { kind: 'port', node: source, port } })` (drop onto a nested field of an object binding writes into that field) |
| `onConnect` from `ctl:*` to `ctl-in`         | `addControlEdge`                                                                                                                                              |
| `onEdgesDelete` (data edge, `via === 'ref'`) | `setBinding(target, port, undefined)`                                                                                                                         |
| `onEdgesDelete` (control edge)               | `removeControlEdges`                                                                                                                                          |
| node dropped into a container frame          | `setParent`                                                                                                                                                   |
| `onSelectionChange`                          | selection                                                                                                                                                     |

`isValidConnection(conn)`: for data handles, `isSubschema(sourcePortSchema, targetPortSchema).ok` (the compiler's own function) and target port currently unbound or bound by a ref (rebinding replaces); for control handles, same scope and the target is not the source. Dragging highlights compatible handles (`--port-valid`) and greys incompatible ones with a tooltip stating the reason. `reactFlowInstance.toObject()` is never called for persistence.

Containers render as `ContainerFrame` group nodes (loop/foreach) with a header (name, `bounds` summary, iteration badge during runs) and `NodeResizer`; child nodes have `parentId` + `extent: 'parent'`. Data edges may cross the frame boundary (outward refs); control edges cannot (the store rejects them).

### 4.3 Live run overlay

`useRunStream(runId)` folds `RunEvent`s into `liveRun.nodeStatus[scope|nodeId] = { status, attempt, latencyMs, costUsd, confidence?, decisionValue?, firedPorts?, error?, iteration? }`; `GENERATION_DELTA` appends to `liveRun.streams[nodeRunId]`. `NodeCard` renders the status as a border (`running` accent pulse, `waiting` and `retry_wait` amber, `completed` green, `failed` red, `skipped` 45 % opacity, `reused` green dashed, `cancelled` grey; the status set is exactly `NodeRunStatusSchema.options`) and the footer summary (`✓ 84 ms · $0.0002`, or the probability ruler for decision nodes). Taken control edges tint `--ok`, pruned edges fade to 30 %. Containers show `3/10` iteration badges from `LOOP_ITERATION_*`/`FOREACH_ITEM_COMPLETED` and a stepper to pick the iteration whose values the inspector shows. Selecting a node during a run opens the Run tab with `NodeRunDetail`.
